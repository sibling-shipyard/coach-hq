# 0032 — Sentry is the primary debug view and observability data rules

- **Status:** Accepted · 2026-08-28 · Tech Lead
- **Area:** cross-cutting (observability, web, iOS, coach-chat API)
- **Context:** Four athletes use the product. Today, debugging broken experiences requires asking athletes what happened from memory. Detailed logs exist in Vercel, but only one operator can access them and they are hard to search on mobile. We need a unified debugging trail across web, API, and iOS with strict privacy boundaries and retention.
- **Decision:** Sentry (hosted in Germany, Developer plan) is the primary searchable debug view for web, backend API, and native iOS; Vercel and Apple logs remain fallback backup sources. Retention is 90 days, fixed by plan on sentry.io and not settable per project — a constraint we accept, not a control we hold. Local iOS event timelines hold at most 200 events or 256 KiB and expire after 24 hours or on sign-out. All API keys, GitHub tokens, auth headers, cookies, and secret credentials must be scrubbed before capture. LLM operations capture model name, token counts (prompt and completion), athlete prompt text, and Gemini reply text correlated by a unique operation ID. The four close-friends beta athletes are treated as opted in for detailed error monitoring; formal athlete controls and consent come in #590. Automatic screenshots and session replay remain disabled.
- **Why:** Centralizing client and API errors in Sentry gives every operator crash, timeout, and LLM-failure visibility from a phone without console access, and correlating by operation ID makes a distributed chat turn debuggable end to end. Scrubbing secrets is the control we actually hold: hosted Sentry offers no retention dial, so the privacy boundary has to be what we send, never how long Sentry keeps it. **Capturing the athlete message and Gemini reply is the load-bearing part, because a failed turn exists nowhere else.** `chat_history.json` is written only by `commitClosingTurn` (`ui/api/coach-chat/_lib/coachTurn.ts`), so a session that never reaches wrap is never committed — and Gemini 5xx responses mean sessions frequently do not reach wrap. On that path `geminiClient.ts` logs the request but never the reply, so even the Vercel fallback holds half the exchange. Sentry is the only record of the turns that break. This is not new exposure either: `geminiClient.ts` already logs the athlete message and the full parsed reply to Vercel on every turn. The choice is not whether chat text leaves the process, it is whether it lands somewhere searchable.
- **Rejected:** Build an internal log warehouse → premature complexity and maintenance burden for four athletes. Enable automatic screen recording or session replays → invasive for privacy and unnecessary when structured timelines and explicit problem reports suffice. Wait for formal user consent UI (#590) before capturing errors → delays resolving critical beta bugs when current athletes have already agreed to participate.
