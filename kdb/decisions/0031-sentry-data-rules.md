# 0031 — Sentry is the primary debug view and observability data rules

- **Status:** Accepted · 2026-08-26 · Tech Lead
- **Area:** cross-cutting (observability, web, iOS, coach-chat API)
- **Context:** Four athletes use the product. Today, debugging broken experiences requires asking athletes what happened from memory. Detailed logs exist in Vercel, but only one operator can access them and they are hard to search on mobile. We need a unified debugging trail across web, API, and iOS with strict privacy boundaries and retention.
- **Decision:** Sentry (hosted in Germany, Developer plan) is the primary searchable debug view for web, backend API, and native iOS; Vercel and Apple logs remain fallback backup sources. Retention is capped at 30 days in Sentry. Local iOS event timelines hold at most 200 events or 256 KiB and expire after 24 hours or on sign-out. All API keys, GitHub tokens, auth headers, cookies, and secret credentials must be scrubbed before capture. LLM operations capture model name, token counts (prompt and completion), athlete prompt text, and Gemini reply text correlated by a unique operation ID. The four close-friends beta athletes are treated as opted in for detailed error monitoring; formal athlete controls and consent come in #590. Automatic screenshots and session replay remain disabled.
- **Why:** Centralizing client and API errors in Sentry gives all operators instant visibility into crashes, API timeouts, and LLM failures from mobile without console access. Capping retention at 30 days and scrubbing secrets protects athlete security while keeping sufficient history to triage recent releases. Correlating web/API requests via operation ID makes distributed AI chat interactions debuggable end to end.
- **Rejected:** Build an internal log warehouse → premature complexity and maintenance burden for four athletes. Enable automatic screen recording or session replays → invasive for privacy and unnecessary when structured timelines and explicit problem reports suffice. Wait for formal user consent UI (#590) before capturing errors → delays resolving critical beta bugs when current athletes have already agreed to participate.
