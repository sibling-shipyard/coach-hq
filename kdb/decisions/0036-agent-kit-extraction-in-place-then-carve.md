# 0036 — agent-kit: extract in place, then carve

- **Status:** Accepted · 2026-09-02 · Tech Lead
- **Area:** cross-cutting
- **Context:** HQ's agent setup (routing gate, role docs, ADR discipline, `.githooks` + CI enforcement) works across Claude Code, Codex, and Cursor today, but only in this repo. The athlete works across several repos and none of the mechanism is HQ-specific — it has just never left HQ. A parallel "generic" tree, built and parameterized before touching HQ's real files, would run two live copies of the same enforcement during the exact window meant to prove improvements propagate without drift.
- **Decision:** Parameterize HQ's live files in place first — `check.sh`'s checks into `checks.conf`, `boot-cost.mjs`'s `ROLES` into `boot-manifest.json`, `AGENTS.md`/`kdb/doc-style.md`/`CONVENTIONS.md`'s portable sections wrapped in `<!-- AGENT-KIT:START id="..." -->` markers — as HQ's real enforcement, behavior-neutral. Only then does `carve-kit.mjs` (`platform/agent-kit/carve-kit.mjs`) read the marked/parameterized files and produce a portable tree, the same copy-verbatim pattern `carve-skeleton.mjs` already uses for `engine/`.
- **Why:** HQ's own `check.sh` and `validate_kdb.py` never went red at any phase (P1–P6, #777/#778/#779/#780/#782/#781) — each change was proven behavior-neutral before the next phase started. A parameterize-in-place-then-carve sequence has one enforcement source at every step; a parallel tree would have two, and the two would drift the moment either changes without the other.
- **Rejected:** Building `platform/agent-kit/` as a parallel tree, parameterized from scratch, dogfooded elsewhere before touching HQ (the plan's original shape) → the drift risk this ADR exists to remove. Porting the 6-agent roster or HQ's routing table into the kit → Coach Phelps, Cyclops, and HQ's specific ownership boundaries are HQ's domain, not the kit's; the kit ships the routing-gate *mechanism* (AGENTS.md §1, never a hook) with placeholder content.
- **Enforces:** A carved section (`<!-- AGENT-KIT:START/END -->`) is HQ's live prose, never a second copy maintained by hand. `checks.conf` and `boot-manifest.json` are the one source `check.sh`/`boot-cost.mjs` read — no hardcoded list survives beside them.
- **How to apply:** Adding a new portable rule? Edit it in HQ's real file (inside markers if it's Tier 2 prose, in `checks.conf`/`boot-manifest.json` if it's Tier 1 config) and re-run `carve-kit.mjs` — never hand-edit a file under `platform/agent-kit/blocks/` or `.../tools/`, they are carve output.
