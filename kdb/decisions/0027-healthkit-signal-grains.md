# 0027 — HealthKit signals are stored at their own grain

- **Status:** Accepted · 2026-08-23 · Tech Lead
- **Area:** cross-cutting (iOS sync, pipeline, web + WidgetKit)
- **Context:** We request eight HealthKit permissions at onboarding and read three. PR #162 fixed that by hanging all four new signals off the activity record. But resting HR, HRV, sleep and VO₂ Max describe a *day*, not a workout: on a two-session Saturday they store twice, on a rest day they vanish — exactly when recovery matters — and VO₂ has to be backdated onto a workout, so no trend can ever be reconstructed from it. That already blocks us: `buildVo2Snapshot()` is hard-stubbed `"unavailable"` and the widget wants a real series. Separately, `hr_stream` runs ~9.4KB per activity, which ADR 0020 already keeps out of the aggregate.
- **Narrows:** ADR 0020, which decided the aggregate projection boundary and — in passing — asserted that `hr_stream` *remains in* `user_data/activities/hist/*.json`. That second half no longer holds. 0020's actual decision, the 20-field scalar allowlist entering the aggregate, is untouched and still binding; only the source-file location of the time series changes here.
- **Decision:** Three write targets, three grains. Activity scalars and `hr_zones` stay in `user_data/activities/hist/<uuid>.json`. The display HR curve moves to a sidecar, `user_data/activities/streams/<uuid>.json`, keyed by the ADR 0014 workout uuid and fetched only on demand. Recovery and fitness metrics go to a day-grain ledger, `user_data/health/daily/YYYY-MM.json`, with one row per day including rest days. Zone seconds are integrated over the full sample set, never the decimated curve, and uncovered time is reported as uncovered rather than smeared into a zone.
- **Why:** Grain mismatch is the defect, so grain is what the storage layout has to encode — a day-grain row is the only shape in which a rest day exists at all. Extending ADR 0020's projection boundary down to the source file buys two more things: Coach reading one activity no longer pulls 200 heart-rate points into context, and backfill becomes an additive write with no read-modify-write of history. Widget logic is untouched by all of this — ADR 0005 already makes widget snapshots the cross-platform contract, so the VO₂ widget lights up on web and iOS from one TypeScript change.
- **Rejected:** PR #162 as-shaped → day-grain data on activity records, the defect above · A single fat activity file including `hr_stream` → ADR 0020 already ruled time series out of the aggregate; keeping them in the source file just moves the cost to Coach's context window · Deriving VO₂ trend from backdated per-workout values → the backdating is what destroys the trend · Uniform-stride downsampling (PR #162's) → silently drops peaks between strides, and on an interval session the peak *is* the signal.
