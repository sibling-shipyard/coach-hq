# Test results summary - 2026-09-15

Cumulative summary of today's full coach-chat testing pass: the coverage-audit fixture work, the
live pass against all 5 real athlete repos, and the fixes and reruns that followed. Raw run-by-run
detail with cost and evidence lives in `test-results/2026-09-15.md`; this file is the condensed
cumulative record.

## Scope

- The full simulation-suite library ran against all 5 real athlete repos (`coach-skanda-2003`,
  `coach-akash-suresh`, `coach-prateekdevaraju`, `coach-date2022`, `coach-shreyas-95-cyber`), plus
  a freshly reset `coach-skanda-testing` for the First Session Protocol scenario.
- Every call ran through OpenRouter (`google/gemini-3.8-flash`), since direct Gemini has no
  credit in this environment.
- Follow-up live reruns happened after each fix, to check whether it actually closed what it
  targeted, not just whether the code changed.
- One local eval-harness run, structural and with no real repo writes, surfaced additional real
  findings while confirming an unrelated CI fix.

## Findings and outcomes

### Fixed and verified

- **Week plan narrated but never saved.** The coach could describe a full week plan in reply
  text without ever committing it to the real week file, with no indication to the athlete that
  anything went wrong. Fixed: an honest correction note now appends to the reply when this
  happens. Verified clean on rerun.
- **`workout_create` narrated as complete, then silently corrected.** On an athlete with an
  active injury flag, the coach would claim a routine was built and saved, then get corrected
  mid-reply once the write failed validation. Fixed: the model now gets a chance to address the
  injury before the reply finalizes. Verified 4/4 clean on rerun.
- **A permanent routine edit misread as a new injury.** A request to permanently change a routine,
  phrased with injury-sounding justification language, got recorded as a new injury disclosure
  instead of the requested edit. Fixed with clearer prompt guidance. Verified 0/3 recurrences on
  rerun.
- **Week-plan detection missed abbreviated weekday names.** The detector that catches an unsaved
  week plan only counted full weekday names, missing a real case that used abbreviations
  instead. Fixed to also match abbreviations, with care taken not to collide with ordinary
  English words that happen to also be day abbreviations. Verified clean on rerun.
- **A concurrency bug in the test tooling itself.** Running the live-test tooling in parallel
  could silently lose results to a write race. Fixed to record each result safely regardless of
  how many test runs happen at once.
- **The automated structural-compliance check had been silently broken for weeks.** It was
  failing on every run for reasons unrelated to any real regression - an expired credential, then
  a malformed test file. Both fixed; the check now actually runs and produces real signal.
- **That same check ran automatically with nobody watching it.** Since no one was reviewing its
  results, it provided real cost with no real safety benefit. Changed to run only when someone
  deliberately decides to, matching every other paid check in this project.
- **Production provider documentation was stale.** It described the production setup
  incorrectly. Corrected to match what's actually running, and recorded properly as a real
  decision rather than an undocumented change.

### Investigated live, not a real problem

- **A returning athlete stating a new season goal without habit language.** Checked whether this
  could get silently narrated without ever saving. Ran live, several times, across three
  different real athletes. Never reproduced. Left alone.
- **All 5 real athletes currently have an empty week plan.** Confirmed this is expected: the
  pipeline that keeps the week's dates current only refreshes the date frame, it never compiles
  real sessions on its own. Not a bug.

### Known gap - not solved

- **A durable training pattern can get silently dropped when stated alongside another request in
  the same message.** The athlete states something worth remembering (a training pattern)
  together with an unrelated request (for example, a coaching-style change) in one message. The
  other request reliably saves correctly; the training pattern is sometimes never recorded, and
  the reply still claims it was. Two different fix approaches were tried live - a stronger prompt
  instruction, then a targeted second-chance correction - and neither reliably closed the gap.
  Left as a known, accepted limitation.
