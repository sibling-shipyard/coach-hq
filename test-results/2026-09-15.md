## Findings

### F1 - `ambiguous-contradiction` on `coach-akash-suresh`: real precondition gap, not a code bug

All 5 real athlete repos' `current_week.json` are currently `data_status: "placeholder"` with
**zero planned sessions in any day** (`user_data/ledger/current_week.json`, confirmed by reading
the real file on all 5, not just akash). The scenario's premise - the athlete contradicts which
planned session they did - has nothing to reconcile against on real data right now. Turn 1
("Did today's Workout B") landed as a `quest_event` write to `progress.json` instead (akash has a
real `block2_strength` progress quest reasonably matching "Workout B, lower body work") - a
sensible fallback given the real data, not a bug. Turns 2-3 correctly narrated the correction in
`reply` but never touched `current_week.json` since there was nothing there to reconcile.
**Separately worth flagging to Tech Lead:** all 5 real athletes currently have an empty week plan
- worth checking whether `engine/scripts/rollover-current-week.mjs` is actually running on
schedule, since this means the real "This Week" view is likely empty for every real athlete right
now, independent of this test.

### F2 - `workout_create` narrated but dropped on athletes with an active injury flag

`coach-akash-suresh` (1 active flag: right hip/glute) and `coach-skanda-2003` (3 active flags)
both hit the same shape on `workout-lifecycle`/`template-edit-permanent`'s first turn ("build me
a routine, no equipment"): the reply narrates a finished routine ("I built this... It's locked in
and ready on your app" - akash, turn 1) but no template file or manifest changed. The existing
same-turn correction mechanism (`formatDroppedActionsCorrection`,
`ui/api/coach-chat/_lib/coachTurn.ts:1569-1573`) catches it and appends an honest note - akash's
actual reply text: *"(Note: couldn't save workout_create this turn - something about that request
didn't go through. If it's still relevant, ask again.)"* - so nothing was silently lost. But the
model's own prose still over-claims completion for one turn before the correction lands. Likely
root cause: `workout_create`'s injury_ack invariant
(`ui/api/coach-chat/_lib/gemini/coachReplySchema.ts:85-88`, "required whenever the athlete has any
active flag") - my fixture's plain "build me a routine" message never prompts the model to
address the injury, so the model may be omitting `injury_ack` and getting the whole action
dropped by `applyWorkoutCreate`'s invariant 7. This reproduced on 2 of the 3 repos with an active
injury flag (`coach-shreyas-95-cyber`, the third, hit an unrelated infra ERROR instead - see I1,
so it's untested for this specific shape). `coach-prateekdevaraju`/`coach-date2022` (0 active
flags) never hit this. Not filed as a code bug outright - could also be a fixture gap (my
`workout-lifecycle`/`template-edit-permanent` messages should probably address the injury
explicitly) - flagging for Tech Lead to decide which.

### F5 (process finding, not a coaching bug) - `coverage-index.json` lost 3 entries to a concurrent-write race

Running 3 parallel streams (`fsp-basic`, `skanda-stream`, `akash-stream`) that each invoke
`npm run test:simulation-suite` against the same HQ worktree meant 3 processes read-modified-wrote
`test-results/coverage-index.json` with overlapping timing. `run-simulation-suite.ts` reads the
whole file, mutates one key in memory, and writes the whole file back
(`ui/scripts/run-simulation-suite.ts:411`, `:419`) - no lock, no re-read-before-write. Real
result: `manual:ambiguous-contradiction`, `manual:session-plan`, and `manual:template-edit-permanent`
entries were silently lost (overwritten away by a later process's write), and `manual:fsp-basic`
kept yesterday's stale `last_run_date`/`last_pass_sha` even though it passed fresh today. I
hand-reconciled `test-results/coverage-index.json` against this day-doc's real results (a
data-bookkeeping correction, not an application-code fix) so the index is accurate for the next
selective-rerun decision - the real, authoritative record of what actually happened either way is
this day-doc plus the raw JSON under `test-results/raw/2026-09-15/manual/`. Flagging as a real gap
in the tool: it isn't safe for concurrent invocations against the same coach-hq checkout, which
this pass needed to keep wall-clock time down. Not fixing per this pass's no-application-code-changes
scope.
